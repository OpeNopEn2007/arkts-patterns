# 性能优化 (Performance Optimization)

## 概述

HarmonyOS 应用性能优化涵盖功耗管理、渲染效率、资源加载和列表/瀑布流性能等方面。

---

## 1. 应用功耗优化

降低应用对系统资源的消耗，延长设备续航。

**关键策略**：
- **减少后台活动**：避免无意义的定时唤醒；使用延迟任务（Work Scheduler）替代轮询
- **优化网络请求**：合并请求、避免频繁断连、使用长连接复用
- **降低屏幕刷新率**：非交互场景降低帧率
- **高效使用传感器**：及时注销不需要的传感器监听
- **资源释放**：不使用的资源及时回收（图片、音频、动画）

> 官方文档：[功耗优化](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V5/power-overview-V5)

---

## 2. 控制渲染范围 (LazyForEach)

**用途**：在长列表、网格、瀑布流中只渲染可视区域内的组件，大幅降低内存和 CPU 开销。

**关键实践**：
- 使用 `LazyForEach` 替代 `ForEach` 渲染大型数据集
- 提供合理的 `keyGenerator` 确保节点复用正确
- 设置 `cachedCount` 控制预加载数量，平衡滑动流畅度和内存
- 避免在子组件中执行耗时操作（如图片解码），应提前处理

```typescript
LazyForEach(this.dataSource, (item: ItemData) => {
  ListItem() { ... }
}, (item: ItemData) => item.id.toString())
```

---

## 3. 提前加载资源

**用途**：利用空闲时间预加载即将用到的资源，减少用户等待。

**策略**：
- 图片预解码：提前将图片解码到内存，显示时直接渲染
- 数据预取：列表滚动前预加载下一页数据
- 页面预加载：使用 `@Builder` 预构建页面结构
- 异步线程加载：使用 TaskPool 在子线程中处理资源加载

---

## 4. 瀑布流性能优化

瀑布流（WaterFlow）布局的性能要点：

**优化措施**：
- 使用 `LazyForEach` 延迟加载
- 合理设置 `columnsTemplate`，避免频繁重排
- 控制 item 的复杂度，减少嵌套层级
- 图片使用统一尺寸或提前裁剪
- 设置 `itemConstraintSize` 避免项目尺寸突变引起重排

---

## 5. 列表性能优化

列表（List 组件）是使用最频繁的高性能场景。

**优化措施**：
- **使用 LazyForEach**：只渲染可见项
- **设置 cachedCount**：根据列表项高度估算，通常 1-3 屏
- **减少 item 嵌套**：扁平化组件层级
- **StickyHeader 谨慎使用**：粘性头部会增加布局计算
- **禁用不必要的动画**：列表滚动时暂停入场动画
- **启用 scrollSnapAlign**：使用对齐提升滚动性能感知
- **使用 ListItemGroup**：分组场景下减少组件实例数

---

## 总结

| 优化方向 | 核心手段 | 效果 |
|----------|----------|------|
| 功耗 | 减少后台活动、合并网络请求 | 延长续航 |
| 渲染范围 | LazyForEach、按需加载 | 降低内存、提升帧率 |
| 资源加载 | 预解码、预取、异步加载 | 减少等待时间 |
| 列表/瀑布流 | 缓存、扁平化、避繁 | 流畅滚动 |
